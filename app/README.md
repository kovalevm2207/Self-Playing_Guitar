# SelfGuitar Desktop

Приложение на C++17, Qt 6.8+, Qt Quick Controls 2 и Qt Serial Port для Windows и Linux / WSL, с передачей нот на Arduino Uno по USB. Интерфейс на QML, обработка каталога и передача на C++; протокол не зависит от Qt.

## Запуск

Готовая локальная сборка: `app/dist/SelfGuitar.exe` или корневой `Start-SelfGuitar.ps1`.

Сборка из исходников: установите Qt 6.8+ Desktop MinGW с Quick, Quick Controls 2, Serial Port и совместимый MinGW. Нужны CMake 3.21+ и mingw32-make. Из корня проекта:

```powershell
./app/build.ps1 -QtRoot C:/Qt/6.8.3/mingw_64 -CompilerBin C:/Qt/Tools/mingw1310_64/bin -Package
```

SDK, сборка и DLL не коммитятся. На этой машине SDK находится в `.codex_tmp/Qt/6.8.3/mingw_64`.

### Linux / WSL

Нужны CMake, g++ и Qt 6.8+ с Quick, Quick Controls 2 и Serial Port. Используйте системный Qt, свой SDK или Nix-окружение ниже. Из корня проекта в WSL:

```bash
bash app/run-linux.sh
# Только сборка и тесты, без окна:
bash app/run-linux.sh --check
# Для другого SDK:
GUITAR_QT_ROOT="$HOME/Qt/6.8.3/gcc_64" bash app/run-linux.sh
```

Для окна в WSL нужен WSLg. Для доступа к плате из WSL понадобится отдельно передать USB-устройство в Linux; после этого приложение использует `/dev/ttyACM*` или `/dev/ttyUSB*`, а не Windows COM-порт. Пока плата не подключена, каталог и избранное доступны, загрузка отключена. На обычном Linux используется тот же скрипт.

Для установленного в этом WSL Nix предусмотрено закреплённое окружение без sudo:

```bash
nix-shell app/shell.nix --run 'bash app/run-linux.sh'
```

Локально проверены сборки Windows (Qt 6.8.3) и Ubuntu 24.04 / WSL (Qt 6.12.0), запуск интерфейса и обе группы тестов. Прошивка Uno собирается: 700 байт RAM, 3606 байт Flash. Реальная передача по USB пока не проверена — плата не подключена.

## Что работает

- Локальный каталог, поиск по названию/автору, фильтр по максимальному количеству струн.
- Выбор аранжировки, подсветка конкретных струн 1–6, длительность и изменение темпа.
- Избранное сохраняется через QSettings.
- Выбор USB-порта, handshake, передача с подтверждением каждой ноты, CRC-16, таймаут и отмена.
- Шесть коротких учебных аранжировок и упражнений. Это фрагменты для разработки, не полные записи песен. В текущем формате ноты идут последовательно, аккордов и пауз нет.

Количество струн вычисляется по событиям, а не вводится вручную. 1 — самая тонкая E4, 6 — самая толстая E2. `app/data/songs.json`: каждая нота — `[номер струны, лад, длительность в мс]`; базовый `bpm` задаёт масштаб при изменении темпа. Допустимы 1–6 струн, 0–24 лада, 50–10000 мс, до 96 нот на аранжировку.

## Подключение Uno

Сначала отдельно загрузите прошивку приёмника (она заменит текущую программу платы):

```powershell
pio run -d firmware/song_receiver -t upload --upload-port COM5
```

Порт замените на фактический. Закройте Serial Monitor и другие программы, занявшие порт. В приложении откройте «Подключение», обновите список, выберите порт и подключитесь. Затем выберите аранжировку и нажмите «Загрузить на Uno».

Прошивка **только принимает ноты**, не управляет выводами моторов/соленоидов. Успех означает получение и проверку CRC, не исполнение мелодии. Данные находятся в RAM и исчезают при перезапуске, отключении питания, новом handshake или отменённой загрузке. EEPROM/SD и управление механикой — следующий этап, требующий карты каналов, калибровки ладов и времени перемещения.

## Проверки

```powershell
cmake -S app -B app/build-core -G 'MinGW Makefiles' -DGUITAR_CORE_ONLY=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build app/build-core
ctest --test-dir app/build-core --output-on-failure
pio run -d firmware/song_receiver
```

Тесты проверяют CRC по эталонному вектору, границы, порядок пакетов, неполную и повреждённую передачу, отмену и заполнение 96 нот. Для снимка реального интерфейса: `SelfGuitar.exe --screenshot C:/absolute/path/preview.png`.

## Переход на телефон

Каталог, протокол и C++-логика пригодны для переноса. Для Android нужно адаптировать компоновку и заменить QSerialPort транспортом через Android USB Host/JNI либо Bluetooth-модулем. Текущая сборка — приложение для ПК; Android APK пока нет.

## Состояние старого проекта

Ветка `software` создана от `main`. Предыдущая история оборудования остаётся в `codex/single-string-wiring`. Пять изменённых файлов сохранены в stash с сообщением `WIP: hardware work preserved before software branch`; восстанавливать его следует на той ветке, не поверх software. Локальные незакоммиченные CAD-скрипты и промежуточные материалы перенесены в игнорируемый `archive/local-hardware`. Документы отчёта и рабочие 3D-модели сохранены и исключены из изменений этой ветки. Удалены воспроизводимые кэши библиотек CAD, сборки и временных host-проверок.
